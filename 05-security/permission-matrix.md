# V1.3.2 权限矩阵

Casdoor 提供角色和功能权限；银行后台不创建本地 IAM 表，以下数据范围由 `employees.org_id`、业务表 `org_id` 和 `employee_id` 共同执行。

| 能力 | 总行管理员 | 机构管理员 | 员工 | 观察者 | 数据范围 |
|---|---|---|---|---|---|
| 查询组织 | 全部 | 本机构及下级 | 本机构 | 授权范围 | 组织编码前缀 |
| 管理组织 | 允许 | 按授权 | 禁止 | 禁止 | 机构/全局 |
| 查询员工 | 全部 | 本机构及下级 | 本机构 | 授权范围 | `org_id` |
| 管理员工 | 允许 | 按授权 | 按授权 | 禁止 | `org_id` |
| 管理触点资产 | 允许 | 按授权 | 按授权 | 禁止 | `org_id` / `employee_id` |
| 绑定、解绑、转交 | 允许 | 按授权 | 按授权 | 禁止 | `org_id` / `employee_id` |
| 管理载体内容 | 允许 | 按授权 | 按授权 | 禁止 | `org_id` / `employee_id` |
| 查询访问事件 | 全部 | 本机构及下级 | 本人/机构 | 授权范围 | 事件 `org_id` / `employee_id` |
| 批量导入 | 允许 | 按授权 | 按授权 | 禁止 | 与页面查询一致 |
| 导出数据 | 允许 | 按授权 | 按授权 | 禁止或只读 | 与页面查询一致 |
| 查询审计 | 全部 | 本机构 | 禁止 | 禁止 | 日志 `org_id` |

最终角色和权限编码必须以 Casdoor 配置及业务确认结果为准。前端菜单和按钮不能替代后端校验。

## 权限码与前端标识映射

Casdoor 是角色和功能权限编码的唯一权威来源。前端不得自行编造、替换或把界面测试编号当作正式权限码。

每项菜单、路由、按钮和 API 动作必须能够逐项追溯到以下映射记录：

| 功能 | Casdoor 权限码 | API 动作 | 菜单 `data-testid` | 按钮 `data-testid` | 状态 |
|---|---|---|---|---|---|
| 待 Casdoor 确认的功能项 | 待确认 | 待确认 | 按前端编号规范填写 | 按前端编号规范填写 | 待确认 |

映射规则：

- 未经 Casdoor 确认的权限码必须标记为“待确认”，不能由前端开发人员自行命名并视为正式权限。
- 权限码与 `data-testid` 必须是两个独立字段，禁止复用或互相推导。
- 权限配置缺失、映射缺失或权限上下文尚未加载完成时，前端按失败关闭处理，并产生可定位但不含敏感信息的配置错误。
- 前端权限只用于菜单、路由和按钮体验；后台仍必须强制执行功能权限和数据范围。
