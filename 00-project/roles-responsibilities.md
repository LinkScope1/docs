# 角色与职责

| 角色 | 主要职责 | 交付物 |
|---|---|---|
| 产品负责人 | 范围、业务规则、优先级、验收 | 需求、规则、验收结论 |
| 项目负责人 | 计划、风险、依赖、会议和变更 | 计划、风险台账、变更记录 |
| 技术负责人 | 架构、技术选型、代码质量和技术决策 | 架构、ADR、技术规范 |
| Python 后端 | FastAPI、业务规则、数据库、集成和任务 | API、Service、迁移、测试 |
| 前端 | 页面、组件、交互和 API 接入 | 页面、组件、前端测试 |
| 数据库负责人 | 数据字典、迁移、索引、权限和备份 | 迁移、数据脚本、恢复验证 |
| 测试负责人 | 测试策略、用例、回归和验收 | 测试报告、缺陷结论 |
| 安全负责人 | Casdoor、权限、数据范围、审计和安全测试 | 安全方案、权限矩阵、审计结论 |
| 运维负责人 | 环境、部署、监控、告警、备份和回滚 | 部署手册、运维手册、演练记录 |
| 外部系统负责人 | Casdoor、LinkForty、NFC 供应方协作 | 外部契约、联调结果 |

## 工作规则

- 每个任务必须有一个主负责人。
- 需求、权限、数据结构和外部协议变更必须记录。
- 阻塞项必须有责任人和截止时间。
- 生产发布必须经过产品、技术、测试和运维确认。

## 双人研发工作包

- 工作包 A：M1、M2、M4，负责操作审计、组织员工主数据和绑定生命周期。
- 工作包 B：M3、M5，负责 NFC 资产与载体内容、LinkForty 集成和访问事件链路。
- 统计与报表、批量导入和异步任务按具体任务协作，不形成新的业务模块或数据所有权。
- 双方共同冻结 `employee_code`、`org_id`、`asset_id`、`employee_id`、绑定有效时间、`linkforty_link_id`、`event_id`、非唯一 `click_id`、`trace_id` 和审计上下文。
- 临时协作、代码评审或结对开发不改变 M1～M5 的数据所有权。
