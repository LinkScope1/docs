# 项目范围说明

## 目标

建设银行触点载体管理系统 MVP，维护组织、客户经理、NFC 触点载体、载体内容、绑定关系、目标资源和路由规则，并接收 LinkForty 事件形成可查询的访问事件和统计指标。

## 系统边界

### 银行后台负责

- M1：后台访问、IAM 和操作审计
- M2：机构与客户经理
- M3：NFC 触点资产和载体内容
- M4：绑定、解绑、转交和历史快照
- M5：目标资源
- M6：路由规则和发布状态
- M7：Webhook 接收、幂等和访问事件关联
- M8：点击、访问、安装和 App 事件统计

### LinkForty Core 负责

- Link、短码和跳转运行时
- 点击、安装和 App 事件原始事实
- 对外 Webhook 投递
- LinkForty 平台自身 API 和数据维护

银行后台对 LinkForty 的写入必须通过 API；读取事件表时使用受限只读账号，不允许读取 `webhooks.secret`，不允许执行 LinkForty DML、DDL 或 TRUNCATE。

## MVP 范围

- 一期只支持 NFC 触点载体。
- Casdoor 作为身份、角色和功能权限权威。
- 本地 IAM 负责主体映射、API 映射和银行组织数据范围。
- `access_events` 不分区，`event_id` 全局唯一，`click_id` 非唯一。
- MVP 不包含银行办理量、办理金额和真实业务转化结果。
- MVP 采用发布到 LinkForty 的路由配置模式，不实现实时点击时动态计算路由。

## 明确不纳入本期

- 二维码、条形码等其他介质的完整流程
- 银行业务办理量和金额接口
- 复杂审批流
- 实时路由计算
- 完整版本可视化回滚
- 自动化 NFC 硬件写卡（除非硬件和 SDK 已确认）

## 当前状态

当前仓库可见的 `core/` 是 LinkForty Core TypeScript 服务，尚未发现独立的 Python 银行后台和完整管理前端。Python 后端、React 前端和银行业务数据库需要按本规范建设或接入实际已有工程。

## 里程碑

| 阶段 | 目标 | 完成标准 |
|---|---|---|
| P0 | 边界和外部契约冻结 | Casdoor、LinkForty、Webhook、NFC 的关键事实有负责人和结论 |
| P1 | 工程基础 | 后端、前端、数据库、Redis、迁移和 CI 可运行 |
| P2 | 主数据闭环 | M1、M2、M3、M4 可完成登录、资产和绑定 |
| P3 | 发布闭环 | M5、M6 可完成资源、规则和 LinkForty 发布 |
| P4 | 事件闭环 | M7、M8 可完成事件接入、统计和导出 |
| P5 | 上线准备 | 权限、安全、性能、备份和回滚验收通过 |

## 成功标准

- 关键业务流程可通过前端完成。
- 所有后端接口都有权限和数据范围校验。
- 事件重复提交不会产生重复 `access_events`。
- LinkForty 外部失败可追踪、重试和人工处理。
- 关键命令和导出都有操作审计。
- 数据库迁移、备份和回滚流程可验证。
