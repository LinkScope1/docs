# NFC/NDEF 集成契约

## 状态

软件契约冻结，真实设备参数待硬件和供应商确认。V1.3.2 只支持 NFC；真实写卡为条件任务，不能以 Mock 成功替代真机证据。

## 必须确认

- 介质类型。
- UID 读取方式。
- NDEF 内容格式。
- 写卡设备和 SDK。
- 读卡设备和 SDK。
- 写入失败返回。
- 读回核验方式。
- 批量写卡能力。

## V1.3.2 软件冻结值

- `read_uid` 必须返回经过规范化的非空 UID 字符串；UID 是资产识别输入，不作为卡内 Payload。
- 写入内容使用 NDEF 文本/URI 记录的适配器抽象；具体记录类型、字符编码和最大字节数由供应商确认单提供，未确认前不得在业务 Service 中自行假定。
- 写入必须区分设备拒绝、超长、连接超时和读回不一致；任一失败不得返回成功状态。
- 成功写入必须执行读回核验，核验值与期望 NDEF 不一致视为失败并写入审计。
- Mock 至少覆盖读 UID、写入成功、写入失败、超长拒绝和读回核验失败；Mock 结果不得标记为真实硬件验收。

## 后端边界

- 后端保存资产和 Payload 业务记录。
- V1.3.2 不定义专属核验结果或外部同步状态字段；如需持久化，必须先变更物理模型。
- 物理写卡通过 `NfcAdapter` 抽象。
- 没有硬件时使用 Mock，不伪造真实核验成功。
