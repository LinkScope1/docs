# 性能测试方案

## 重点场景

- 组织和资产列表分页。
- 绑定冲突校验。
- Webhook 并发接收。
- 访问事件查询。
- 统计查询。
- 大数据量导出。

## 测试指标

- 平均响应时间。
- P95/P99 响应时间。
- 吞吐量。
- 错误率。
- 数据库连接池使用率。
- Celery 任务积压。
- 统计查询耗时。

V1.3.2 保守门槛：列表接口 P95 ≤ 500 ms，访问事件接口 P95 ≤ 1 s，统计接口 P95 ≤ 2 s，同步导出 P95 ≤ 5 s。

- 错误率必须小于 1%，Celery 队列积压必须小于 100，发布后观察窗口为 30 分钟。
- P99 必须记录，但本版本只作为观测指标，不作为额外关闭门槛；超过 P95 门槛时按回滚/延期规则处理。
- 报告必须记录固定测试数据量、并发量、数据库连接池、慢查询、Redis 和 Celery 指标。没有这些命令结果不得标记性能通过。

## 执行与证据规则

当前延期阶段只冻结阈值和执行入口，不以本地单元测试、Mock 或空数据耗时替代性能报告。进入集成测试阶段后，使用隔离测试数据库、独立 Redis/Celery 队列、固定数据量、固定并发量和固定环境配置，保存以下证据：

- 环境快照：数据库版本、迁移版本、连接池、Redis 和 Worker 配置；
- 压测结果：列表、访问事件、统计和同步导出的 P95/P99、吞吐量和错误率；
- 依赖指标：慢查询、连接池使用率、Redis 延迟和 Celery 队列积压；
- 统计分支：无外部 Link 的空数据成功、点击 API 可用、安装/App API 不可用返回 `503 DATA_SOURCE_UNAVAILABLE`；
- 观察结果：连续 30 分钟的指标快照、是否超过阈值及延期/回滚判断。

执行入口为本文件的固定场景和测试环境 Runbook；报告完整、命令结果可复现且负责人确认前，`T-PERF-001` 保持 `阻塞待确认`。P99 只作观测指标，不增加额外关闭门槛。
