# 3. V1.3.2 系统范围和边界

V1.3.2 的正式范围为 8 张银行业务表、1 张横向导入任务表、8 张 LinkForty 外部现有表，以及 Casdoor 外部身份边界。银行库只维护银行业务主数据和审计投影。

| 边界对象 | V1.3.2 定位 | 银行后台约束 |
| --- | --- | --- |
| 银行业务数据库 | 8 张本地业务表 | 由银行后台负责数据所有权和演进 |
| Casdoor | 身份、角色与功能权限权威 | 通过 OIDC 供 BFF 服务端兑换和验证 JWT，并读取 employee_code；不建立本地权限投影 |
| LinkForty | 链接、点击和 Webhook 等底层能力 | 写入走 API；读取受限；不直接迁移或修改外部表 |
| NFC | 一期触点载体类型 | 资产类型固定为 NFC，写入和核验通过适配能力完成 |

> 外部表保护：银行系统不得对 LinkForty 物理表执行 DDL、DML、TRUNCATE 或迁移，不得通过数据库直读、记录或输出 Webhook 密钥值；受控 Core API provisioning 仅可向银行配置服务一次性交付验签运行时配置。

# 4. 模块划分原则

- 以数据所有权为第一原则：每张银行业务表只有一个负责写入和状态解释的模块。

- 模块按业务内聚性划分，不按照开发人员数量机械拆分；两人协作通过研发工作包解决。

- 外部系统、设备适配、批量导入、幂等、审计和异步任务属于外部或横向能力，不单独占用 M 编号。

- 跨模块读取不得改变数据所有权；跨模块写入必须通过责任模块的业务规则执行。

- 银行业务表不依赖数据库级级联删除，关系完整性由 Service 和 Repository 的事务校验保证。

# 7. M1～M5 模块职责与边界

## 7.1 M1 后台访问与操作审计

**定位：**形成可信的后台访问上下文，并为员工操作和系统任务提供统一审计记录。

**数据所有权：**只拥有 operation_logs；该表只追加，不由其他模块直接修改。

**输入：**BFF 规范化 `AccessContext`、trace_id、员工和组织上下文、操作类型、对象标识、执行结果及必要的前后值。

**输出：**有效的员工访问上下文，以及可按 trace_id、操作员工、对象和时间追踪的审计记录。

**负责事项：**通过 BFF 边界校验 JWT 签名、issuer、audience、nonce 和过期时间；使用 employee_code 定位启用员工；记录登录、管理、绑定、导入、导出和外部同步等操作。

**不负责事项：**不保存本地身份权限投影，不保存密码、Token、密钥或其他敏感凭证，不决定其他业务对象状态。

**依赖：**依赖 Casdoor 身份声明以及 M2 的 employees；系统任务允许 employee_id 为空，但必须保留 trace_id。

**验收重点：**员工不存在或停用时拒绝访问；关键操作审计完整；失败和部分成功可追踪；敏感凭证不进入日志。

## 7.2 M2 组织与员工管理

**定位：**维护组织编码层级、员工主数据和员工直接所属组织，为所有模块提供数据责任范围基线。

**数据所有权：**拥有 organization_units 和 employees。

**输入：**组织编码与名称、状态、区位信息、联系人信息，以及员工编码、姓名、直接所属 org_id 和状态。

**输出：**可按 org_code 前缀查询的组织层级、员工主数据、员工直接所属组织和数据范围根节点。

**负责事项：**校验 org_code 格式、前缀关系和全局唯一性；维护员工编码唯一性和启停状态；通过 employee_code 对接 Casdoor Claim。

**边界：**组织层级只由 org_code 前缀表达，不另设父组织字段或组织层级字段；员工只保存一个直接所属 org_id。

**字段归属：**location_code 和 door_no 属于组织信息，不属于触点资产投放位置。

**验收重点：**根组织和下级编码规则、组织和员工唯一性、员工启停、直接组织归属、手机号密文与脱敏值、后端范围校验。

## 7.3 M3 NFC 触点资产与载体内容管理

**定位：**管理 NFC 触点资产、可复用地址页面、卡内实际写入内容、当前责任范围和 LinkForty 外部逻辑引用。

**数据所有权：**拥有 touchpoint_assets 和 touchpoint_payloads。

M3 同时拥有 `touchpoint_address_pages`。地址页面是银行后台可复用的内容主数据，不是 `target_resources` 或 `routing_rules`；其 `content_type` 固定为 1 小程序、2 APP、3 网页。`url` 是原始/展示值，只做首尾空格清理；`target_url` 是目标配置，进入 Core 前由 Service 按内容类型解析。小程序要求公开 HTTPS Universal Link，APP 使用 `card-switch-demo` 的 `app-open.html` Bridge，网页直接使用目标 URL。

**输入：**asset_code、asset_type、carrier_uid、责任 org_id/employee_id、资产状态，以及 Payload 类型、值、来源、提供方和外部链接标识。

**输出：可查询和导入的资产主数据、卡内实际内容、当前责任组织和员工，以及 LinkForty 逻辑引用；外部调用结果作为审计上下文提交 M1。**

**负责事项：**保证 asset_code 全局唯一和非空 carrier_uid 唯一；一期 asset_type 固定为 NFC；维护资产状态和载体内容状态。

**边界：**Payload 表示卡内实际写入内容，不代表最终跳转目标；`linkforty_link_id` 只是 LinkForty 链接逻辑引用；不直接修改外部平台表。地址页面目标发生变化时，M3 更新同一个 Core Link 并同步 Payload 的 `target_url` 快照，不修改 `payload_value`，因此不需要重新写 NFC。

**依赖：**依赖 M2 的责任组织和员工；通过 LinkForty API 与 NFC 适配能力完成外部登记、写入或核验。

**验收重点：资产编码、物理 UID、NFC 限定、资产和内容状态、地址页面内容类型、责任范围及逻辑引用正确；单条和批量目标切换、Core 外部状态冲突、失败补偿和审计可通过 M1 的 `trace_id` 追踪，不依赖 Payload 同步状态字段。**

## 7.4 M4 触点载体员工绑定管理

**定位：**以追加历史方式维护触点载体与员工的当前及历史绑定关系。

**数据所有权：**拥有 touchpoint_employee_assignments。

**输入：**asset_id、org_id、employee_id、生效时间，以及解绑原因码和解绑说明。

**输出：**当前有效或已解绑的绑定记录、有效时间区间和解绑原因。

**负责事项：**保证同一资产的有效绑定时间区间不重叠；绑定记录只追加，不覆盖历史；解绑时保留失效时间和原因。

**边界：**不保存组织、支行或员工名称快照；历史查询展示当前主数据名称，不保证还原绑定发生时的名称。

**依赖：**依赖 M2 的组织和员工状态、M3 的资产及其当前责任信息。

**验收重点：**有效区间冲突、当前绑定识别、解绑闭环、历史记录保留、跨组织约束和责任信息一致性。

## 7.5 M5 访问事件接入与关联管理

**定位：**接收 LinkForty 事件并形成银行侧幂等投影，关联触点资产、事件时命中的绑定、组织和员工。

**数据所有权：**拥有 access_events。

**输入：**event_id、click_id、事件元数据及 LinkForty 逻辑关联信息。

**输出：**访问事件记录、asset_id、binding_id、org_id、employee_id、关联状态、原因和完成时间。

**负责事项：**event_id 作为全局唯一幂等键；click_id 允许重复且仅作逻辑引用；维护待关联、成功、待重试和失败状态。

**边界：**事件状态只表示资产、组织和员工关联；不保存最终跳转目标、运行时规则或目标快照；不直接修改 LinkForty 表。

**依赖：**依赖 LinkForty 事件或受限读取、M3 的资产与内容、M4 的事件时点绑定。

**验收重点：**缺失或重复 event_id、重复 click_id、关联失败、重试状态、首次 received_at 不更新和外部只读边界。

# 8. 外部系统与横向能力

| 能力 | 类型 | 职责 | 模块编号规则 |
| --- | --- | --- | --- |
| Casdoor | 外部身份边界 | 签发 JWT，维护身份、角色和功能权限 | 不占 M 编号 |
| LinkForty | 外部触点平台 | 链接、点击、Webhook 和底层访问能力 | 不占 M 编号 |
| NFC Adapter | 设备适配 | 实体卡写入、读取和核验 | 不占 M 编号 |
| 批量导入 | 横向应用能力 | 预校验、幂等、逐行结果、明确的更新或新增 | 由 M3、M4 等责任模块执行 |
| 操作审计 | 横向治理能力 | 所有管理操作和批次均提交审计上下文 | 数据归属 M1 |
| Worker / Celery | 异步技术能力 | LinkForty 调用重试、事件重试、批量导入和补偿；执行结果由 M1 审计 | 不占 M 编号 |

## 8.1 批量导入预留规则

- 预留载体内容批量修改、载体与员工绑定关系批量修改、载体与载体内容关系批量修改三类模板。

- 组织使用 org_code、员工使用 employee_code、载体优先使用 asset_code，可辅助使用 carrier_uid。

- 载体内容使用 asset_code 与 payload_type 的组合，或使用明确的内容记录 ID。

- 匹配到记录则更新；未匹配且必填字段完整则新增；缺少某行不推导删除、停用或解绑。

- 导入必须支持预校验、幂等键、逐行结果和失败原因；每批导入写入 operation_logs。

- V1.3.2 不创建导入批次表和导入明细表，异步导入启用时再扩展模型。

# 9. 数据所有权与模块依赖

| 数据域 | 责任模块 | 主要依赖或使用方 | 写入边界 |
| --- | --- | --- | --- |
| 操作审计 | M1 | M2～M5 和系统任务提交上下文 | 只有 M1 写 operation_logs，记录只追加 |
| 组织、员工 | M2 | M1 认证映射；M3、M4、M5 责任校验 | 其他模块不得绕过 M2 修改主数据 |
| 资产、内容 | M3 | M4 绑定；M5 事件关联 | 其他模块通过 M3 规则维护责任信息 |
| 绑定历史 | M4 | M5 事件时点关联 | 记录只追加，不覆盖历史 |
| 访问事件 | M5 | 审计查询或后续只读使用 | event_id 唯一，关联状态由 M5 解释 |
| LinkForty 运行数据 | LinkForty | M3、M5 通过 API、事件或受限读取使用 | 银行模块不得直接修改外部表 |

> 协作规则 跨模块调用可以读取责任模块数据或提交业务命令，但不得改变表的唯一所有者、绕过状态规则或把外部表纳入银行数据库迁移。

# 10. 认证、数据范围与跨系统数据流

## 10.1 身份与数据范围

1. 浏览器访问银行后台 BFF；BFF 将用户重定向到 Casdoor Authorization Endpoint。

1. Casdoor 回调 BFF；FastAPI 服务端兑换 code 并验证 JWT 签名、issuer、audience、nonce 和过期时间。

1. BFF 从规范化 Claims 获取 employee_code，并由 M2 查询 employees；浏览器只收到 HttpOnly Session Cookie。

1. 员工不存在或停用时拒绝访问。

1. 查询、导出和导入按员工所属 org_id 以及本人 employee_id 执行后端数据范围过滤。

## 10.2 资产、内容与 LinkForty

1. M3 维护 NFC 资产、卡内实际内容和当前责任范围。

1. touchpoint_payloads.linkforty_link_id 逻辑引用 LinkForty.links.id。

1. 银行后台通过 LinkForty API 执行必要的外部调用；业务表只保存 linkforty_link_id 等必要逻辑引用，执行结果写入 operation_logs 并保留 trace_id。

1. M1 记录管理操作和外部同步结果，不记录密钥或 Token。

## 10.3 访问事件关联

1. LinkForty 事件通过 event_id、click_id 和外部链接标识进入银行后台。

1. M5 以 event_id 执行幂等投影，click_id 仅用于逻辑关联。

1. M5 结合 M3 资产与内容、M4 绑定历史确定资产、组织和员工。

1. M5 写入 access_events 的关联状态、原因和完成时间；失败进入待重试或最终失败。

# 11. 后端分层和异步任务落点

| 层次 | 职责 | V1.3.2 实施约定 |
| --- | --- | --- |
| Router | 协议适配 | 接收请求、解析认证上下文、返回统一响应；不直接写 SQL 或调用外部系统 |
| Service | 业务规则 | 组织编码、数据范围、绑定时间冲突、导入预校验和审计编排 |
| Repository | 数据库访问 | SQLAlchemy 查询、事务、索引和约束；不承载外部平台业务 |
| Integration Adapter | 外部调用 | Casdoor Claim、LinkForty API、Webhook 和 NFC 适配及重试 |
| Worker / Celery | 异步任务 | LinkForty 调用重试、事件重试、批量导入和补偿；执行结果由 M1 审计 |
| Alembic | 数据库演进 | 只演进银行侧 8 张业务表及横向导入任务表；禁止修改 LinkForty 平台表 |

# 12. 两人研发工作包划分

模块数量保持五个，研发执行按业务依赖和数据表数量组合为两个工作包。工作包是人员分工，不改变模块编号、数据所有权或跨模块写入规则。

| 工作包 | 负责模块 | 主要数据表 | 研发重点 | 主要交接 |
| --- | --- | --- | --- | --- |
| A | M1～M3 | operation_logs<br>organization_units<br>employees<br>touchpoint_assets<br>touchpoint_payloads<br>touchpoint_address_pages | 访问上下文、审计、主数据、NFC 资产、地址页面和载体内容 | 向 B 提供组织/员工/资产/Payload/地址页面校验、外部 Link 引用和审计上下文 |
| B | M4～M5 | touchpoint_employee_assignments<br>access_events | 绑定、解绑、调拨、事件幂等、资产关联和访问事件 | 向 A 的审计能力写入绑定及事件处理结果 |

## 12.1 共同冻结的协作契约

- 身份与范围：employee_code、org_id、employee_id 及停用员工拒绝规则。

- 资产与绑定：asset_id、employee_id、effective_from、effective_to 和绑定状态。

- 外部链接：linkforty_link_id 的 UUID 语义和只作为逻辑引用的边界。

- 事件幂等：event_id 全局唯一，click_id 非唯一。

- 治理上下文：trace_id、操作对象、执行结果、失败摘要和补偿状态。

## 12.2 建议协作节奏

| 阶段 | 工作包 A | 工作包 B | 共同验收 |
| --- | --- | --- | --- |
| 第一阶段 | M1～M3 基础能力、主数据和触点资产 | 准备 M4～M5 接口和依赖 | 身份、范围、资产、Payload 和审计字段契约 |
| 第二阶段 | 提供稳定的组织、员工、资产和 Payload 基础 | M4～M5 绑定生命周期、事件幂等与关联 | 资产—绑定—事件关联链路 |

## 13.2 V1.3.2 确认结论

- 字段事实：V1.3 的 touchpoint_payloads 详细字段表原本没有 external_sync_status。

- 系统边界：LinkForty 是外部平台，其运行状态不复制为银行侧业务状态。

- 职责闭环：M3 负责外部调用，Worker 负责重试和补偿，M1 负责结果审计。

- 版本决议：本次确认作为 V1.3.2 物理模型修订结论，并同步到 V3.1。

> 确认结论 V1.3.2 明确 touchpoint_payloads 不定义 external_sync_status。M3 负责 LinkForty 调用和外部同步编排，Worker 执行重试与补偿；银行业务表只保存 linkforty_link_id 等必要逻辑引用，成功、失败和补偿结果由 M1 通过 operation_logs 与 trace_id 审计。本次不新增同步时间、错误摘要、重试次数或替代字段。
