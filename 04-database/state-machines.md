# V1.3.2 状态转换规则

状态转换由对应模块的 Service 执行。Router 不直接写状态，Repository 不决定是否允许转换。状态字段的枚举值以 [数据物理模型与数据字典](./data-dictionary.md) 为准；本文只维护允许的转换、前置条件和终态规则。除明确允许的转换外，其余转换统一拒绝并返回 409 STATE_CONFLICT。

## 1. M2 组织状态

| 当前状态 | 目标状态 | 是否允许 | 前置条件 |
| --- | --- | ---: | --- |
| 1 启用 | 0 停用 | 是 | 不存在启用下级组织、启用员工、非作废资产或当前有效绑定 |
| 0 停用 | 1 启用 | 是 | 组织编码有效；除根组织外，上级编码对应组织必须存在且启用 |
| 相同状态 | 相同状态 | 幂等成功 | 不重复写无意义状态变更日志 |

- 根组织编码为 1，不允许通过普通业务接口停用。
- 停用组织不删除组织、员工、资产、事件或操作日志。
- 停用组织后禁止在该组织下新增、调入或启用员工和资产。

## 2. M2 员工状态

| 当前状态 | 目标状态 | 是否允许 | 前置条件 |
| --- | --- | ---: | --- |
| 1 正常 | 0 停用 | 是 | 已结束或转交全部当前有效绑定，并清除资产和内容的当前员工责任引用 |
| 0 停用 | 1 正常 | 是 | 直接所属组织存在且启用，员工编码仍满足唯一约束 |
| 相同状态 | 相同状态 | 幂等成功 | 不重复执行关联变更 |

- 员工停用后不得建立新绑定、创建其责任数据或通过 Casdoor映射获得业务访问权限。
- 历史绑定、事件和操作日志继续显示当前员工主数据，不清空历史逻辑引用。
- 员工调动不是单纯状态转换；必须按“结束当前绑定或转交 → 修改 employees.org_id → 重新建立责任关系”的业务命令执行。

## 3. M3 触点资产状态

| 当前状态 | 目标状态 | 是否允许 | 前置条件 |
| --- | --- | ---: | --- |
| 0 库存 | 1 启用 | 是 | 责任组织启用；载体基础信息完整；需要使用载体内容时至少存在一条有效内容 |
| 0 库存 | 2 停用 | 是 | 用于质检隔离、异常库存等场景，必须记录原因 |
| 0 库存 | 9 永久作废 | 是 | 不存在当前有效绑定 |
| 1 启用 | 2 停用 | 是 | 停止对外使用；当前绑定是否同时解绑由显式命令决定，不隐式删除历史 |
| 1 启用 | 9 永久作废 | 是 | 必须先结束当前有效绑定，并记录作废原因 |
| 2 停用 | 1 启用 | 是 | 责任组织启用，当前责任员工非空时必须正常，载体信息满足启用条件 |
| 2 停用 | 9 永久作废 | 是 | 必须先结束当前有效绑定，并记录作废原因 |
| 9 永久作废 | 任意其他状态 | 否 | 永久作废不可恢复 |
| 相同状态 | 相同状态 | 幂等成功 | 不重复写状态 |

- 绑定、解绑和转交不隐式改变 asset_status；如业务同时要求启停，必须在同一显式命令中校验并记录。
- 永久作废只终止后续业务使用，不删除载体、内容、绑定、事件或操作日志。

## 4. M3 载体内容状态

| 当前状态 | 目标状态 | 是否允许 | 前置条件 |
| --- | --- | ---: | --- |
| 0 待登记 | 1 有效 | 是 | payload_type、payload_value 和来源完整；所属资产存在且未永久作废 |
| 0 待登记 | 2 停用 | 是 | 记录停用原因 |
| 0 待登记 | 3 失效 | 是 | 内容不可使用或核验失败，记录原因 |
| 1 有效 | 2 停用 | 是 | 人工或业务停用 |
| 1 有效 | 3 失效 | 是 | 内容不可恢复、外部对象不存在或内容核验确认失效 |
| 2 停用 | 1 有效 | 是 | 重新校验内容完整且所属资产未永久作废 |
| 2 停用 | 3 失效 | 是 | 确认内容不可恢复 |
| 3 失效 | 任意其他状态 | 否 | 失效记录保留，不恢复原记录；需要重新使用时新增或登记新内容 |
| 相同状态 | 相同状态 | 幂等成功 | 不重复写状态 |

- linkforty_link_id 是外部逻辑引用，不形成银行业务同步状态机。
- LinkForty调用成功、失败、重试和补偿通过 trace_id、任务日志和 M1 operation_logs追踪。

## 4.1 M3 可复用地址页面状态

| 当前状态 | 目标状态 | 是否允许 | 前置条件 |
| --- | --- | ---: | --- |
| 1 启用 | 0 停用 | 是 | 记录操作人、trace_id 和审计详情；不删除历史引用 |
| 0 停用 | 1 启用 | 是 | 页面责任组织存在且启用，操作者具有地址页面管理权限 |
| 相同状态 | 相同状态 | 幂等成功 | 不改变既有 Payload，不自动重写 NFC 或 LinkForty |

- 新建地址页面默认启用；地址编码和责任组织创建后不可修改。
- 只有启用地址页面才能出现在目标资产的选择下拉框中。已关联后再停用，不会使历史 Payload 失效，也不会自动改写 `payload_value` 或删除 `target_url` 快照。
- `url` 只做首尾空格清理，不做通用 HTTP/HTTPS 审查；进入 Core 时，小程序必须是公开 HTTPS Universal Link，APP 必须解析为公开 HTTPS Bridge URL，网页按 Core 的目标校验处理。
- 地址页面的目标配置或 APP Bridge 配置变化触发既有关联 Payload 的异步重新应用任务；内容类型、地址编码和责任组织创建后不可修改；展示名称、说明和无关元数据变化不触发任务。任务逐条校验外部快照，Core 更新失败或银行落库失败时执行补偿。

## 5. M4 绑定状态

| 当前状态 | 目标状态 | 是否允许 | 前置条件 |
| --- | --- | ---: | --- |
| 新记录 | 1 当前有效 | 是 | 资产未永久作废；员工存在且正常；绑定时间区间不与现有记录重叠 |
| 1 当前有效 | 2 已解绑 | 是 | 设置 effective_to，且结束时间晚于 effective_from；记录解绑操作人和原因 |
| 2 已解绑 | 1 当前有效 | 否 | 历史记录不得恢复；重新绑定必须新增记录 |
| 2 已解绑 | 2 已解绑 | 幂等成功 | 不重复修改结束时间和原因 |

- 绑定历史不得删除或被新绑定覆盖；“只追加”表示新绑定新增记录，解绑只结束当前记录并保留历史。
- 同一资产最多存在一条 assignment_status = 1 的当前绑定，有效时间区间不得重叠。
- 绑定成功时在同一事务内同步资产和全部所属内容的 org_id、employee_id。
- 解绑后资产和内容的 employee_id 置空，org_id 保留为解绑前责任组织；后续调拨必须使用显式命令修改组织。
- 转交采用“结束旧绑定 + 新增新绑定 + 同步资产和内容责任范围”的单一事务，不直接覆盖旧绑定员工。

## 6. M5 访问事件关联状态

| 当前状态 | 目标状态 | 是否允许 | 前置条件 |
| --- | --- | ---: | --- |
| 新事件 | 0 待关联 | 是 | 签名通过、event_id存在且唯一、已解析到本地 asset_id |
| 0 待关联 | 1 成功 | 是 | 完成资产、事件时间绑定、组织和员工关联 |
| 0 待关联 | 2 待重试 | 是 | 临时数据源或依赖不可用，记录可重试原因 |
| 0 待关联 | 3 失败 | 是 | 确认不可恢复或超过重试策略 |
| 2 待重试 | 1 成功 | 是 | 重试后关联完成 |
| 2 待重试 | 2 待重试 | 是 | 仍为临时错误；重试次数和下次时间由 Worker任务记录 |
| 2 待重试 | 3 失败 | 是 | 超过重试策略或确认不可恢复 |
| 1 成功 | 任意其他状态 | 否 | 成功事件为终态 |
| 3 失败 | 任意其他状态 | 否 | 最终失败为终态；人工重放必须产生受审计的补偿命令 |

- 缺少 event_id 或签名错误的 Webhook 在进入业务事件表前拒绝。
- 重复 event_id 返回首次处理结果或幂等成功，不新增事件。
- 相同 click_id、不同 event_id 允许分别保存。
- access_events.asset_id 非空，因此无法解析本地资产的原始投递不写入该表；由 LinkForty投递记录或任务日志保留并重试。

## 7. M1 操作日志

operation_logs 没有可变状态机：

- 每次操作结果写入新日志，operation_result 为 1成功、2失败或3部分成功。
- 日志创建后禁止更新和删除。
- 成功业务审计与本地业务数据在同一事务写入；失败审计在业务事务回滚后使用独立短事务写入。
- 不得在日志中保存密码、Token、JWT、Webhook Secret、数据库密钥或未脱敏敏感数据。

## 8. V1.3.2 冻结规则

以下规则自 `V1.3.2-FREEZE-001` 起为正式业务规则，不再使用“当前推荐值”表述。实现、测试和验收必须以这些规则为准；规则变更必须先走版本变更评审。

| 事项 | 正式冻结值 | 影响模块 |
| --- | --- | --- |
| 根组织是否允许停用 | 不允许普通业务接口停用 | M2、M1 |
| 资产启用是否要求有效内容 | 需要对外使用内容时至少一条有效内容 | M3 |
| 绑定是否自动启用资产 | 不自动改变 asset_status | M3、M4 |
| 解绑后资产 org_id 如何处理 | 保留解绑前责任组织，employee_id置空 | M3、M4 |
| 内容失效后是否可恢复 | 原记录不可恢复，需要新增或重新登记内容 | M3 |
| 无法解析本地资产的Webhook是否写access_events | 不写；由投递记录或任务日志保留并重试 | M5 |

### 8.1 冻结不变量

- `assignment_status = 1` 必须同时满足 `effective_to IS NULL`；`assignment_status = 2` 必须有 `effective_to`，且 `effective_to > effective_from`，解绑原因类型必填。
- 绑定只允许立即生效；预约绑定、预约解绑和未来生效时间延期到 V1.4。
- 同一资产只能有一条当前有效绑定，历史绑定只追加、不可删除、不可恢复。
- `access_events.asset_id` 必须非空；签名、`event_id` 或本地资产解析失败时不得写入访问事件表。
- `linkforty_link_id` 非空时全局唯一；一个外部 Link 不得关联多个载体内容记录。
- `operation_logs` 只追加；成功审计和业务变更同事务，失败审计使用独立短事务补写。
