# 数据库规范

## 文档职责与权威来源

- 表、字段、类型、默认值、数据库约束、索引和枚举值以 [数据物理模型与数据字典](./data-dictionary.md) 为准。
- 逻辑外键、引用校验、责任范围一致性和删除前检查以 [数据关系与逻辑外键规则](./erd.md) 为准。
- M1–M5 状态转换、前置条件、终态和幂等行为以 [状态转换规则](./state-machines.md) 为准。
- 数据保留、归档和测试数据处理以 [数据生命周期](./data-lifecycle.md) 为准。
- 数据库账号、访问权限和 LinkForty 只读边界以 [数据库权限方案](./db-permissions.md) 为准。

本文件只保留跨表通用的数据库规范，不重复维护各表字段、逻辑外键清单或状态转换明细。

## 基本规则

- 数据库使用 PostgreSQL 14+。
- 银行业务表使用 `bank_admin` Schema。
- 迁移使用 Alembic。
- BIGINT 主键通过 API 以字符串传输。
- PostgreSQL UUID 保留 UUID 类型。
- 时间字段使用带时区类型。
- `access_events` 不分区。
- 事件幂等键和外部点击引用必须遵循数据字典中的字段约束与索引定义。
- JSONB 只用于低频扩展属性。
- V1.3.2 业务库保留 7 张业务表，并增加横向 `import_batches` 批量导入任务表；不创建 `iam_*`、`target_resources` 或 `routing_rules`。

## 表和字段

- 表名和字段名使用 snake_case。
- 状态字段必须在数据字典中列出枚举值，并在状态转换规则中定义允许的转换。
- 创建和修改时间统一命名。
- 创建人和修改人使用逻辑引用。
- 绑定历史不保存名称快照；新绑定新增记录，解绑只结束当前记录，禁止删除或覆盖历史。
- 业务表关系使用逻辑外键，具体校验和删除规则不得在本文件重复定义。

## 迁移

- 每个数据库变更必须有 Alembic revision。
- 迁移必须可重复检查。
- 生产迁移前必须备份。
- 大表变更必须评估锁和耗时。
- 不允许通过应用启动时静默修改生产表。
